Architecture & model

1 · Layered / ring architecture

Devices and the HID feed events into the ring-0 core; views read from the authoritative store. Only the core writes truth.

2 · Event lifecycle — interrupt to context switch

An event is captured deterministically, then the mediator decides (non-deterministically) whether it earns a context switch. Not every interrupt preempts.

flowchart LR
    A["Something happens
(event)"] --> B["Interrupt
webhook/push
(poll = fallback)"]
    B --> C["Mode switch
ring 3 to ring 0"]
    C --> D["Mechanism (deterministic)
capture + dedupe + record"]
    D --> E["Policy (mediator)
triage / prioritize / map to ticket"]
    E --> F{"Context switch?
priority / masking"}
    F -- "yes" --> G["Preempt: prompt human
scoped authority + confirm"]
    F -- "no" --> H["Enqueue ticket
no interruption"]

3 · Latency hierarchy

The same memory hierarchy a real OS manages, scaled ~10⁹ into human-perceptible time. Delay is the organizing principle, not a bug.

flowchart TB
    r["SQLite local r/w — ms  (RAM tier)"]
    m["Mediator inference — seconds  (compute)"]
    n["Notion sync — seconds to min  (I/O)"]
    p["Email / calendar poll — minutes  (slow peripheral)"]
    h["Human answers prompt — min to hours  (slowest device)"]
    r --> m --> n --> p --> h

Execution & orchestration (ADR-0003)

7 · Ticket execution state machine

A ticket's lifecycle once it exists — including blocked, waiting-on-human, failed/retrying, and compensating. Tags reference POLICY Laws/Limits.

stateDiagram-v2
    [*] --> Issued
    Issued --> Ready: deps met + admitted
    Ready --> Deferred: scheduled (Clock, ADR-0004)
    Deferred --> Ready: timer fires
    Ready --> Dispatched: dispatcher assigns a worker
    Dispatched --> Running: worker starts (capability lease)
    Running --> Blocked: awaiting dependency/resource
    Blocked --> Ready: unblocked
    Running --> WaitingHuman: needs input / confirm [L5]
    WaitingHuman --> Running: input received
    Running --> Done: success
    Running --> Failed: error / timeout
    Failed --> Retrying: attempts < max [C7]
    Retrying --> Ready
    Failed --> Compensating: no retry, partial effects
    Compensating --> Dropped
    Running --> Cancelled: job-control (human)
    Done --> [*]
    Dropped --> [*]
    Cancelled --> [*]

8 · Dispatch flow — run queue to worker

One dispatcher pulls READY tickets and routes each to its executor kind (agent / automation / human), under a capability lease, journaling write-ahead before any act.
